# 反向代理配置

## 什么是反向代理

用户请求先到 Nginx（80端口），Nginx 再把请求转发给后端的 Tomcat（8080端口），Tomcat 处理完后把结果原路返回给用户。

用户全程只接触 Nginx 的地址，不需要知道后端有 Tomcat。

## 本环境配置目标

- 用户访问 http://192.168.149.128
- Nginx 接收请求，转发到本机 8080 端口的 Tomcat
- 用户看到的是 Tomcat 的页面，但地址栏是 Nginx 的地址

## 配置位置

- Nginx 主配置文件：/etc/nginx/nginx.conf
- 反向代理在 server 块中配置

## 反向代理核心配置

在 nginx.conf 中找到 server 块，写入：
nginx
server {
    listen 80;
    server_name _;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
配置项说明：

- `listen 80`：Nginx 监听 80 端口，作为对外入口
- `server_name _`：匹配所有域名或 IP 访问
- `location /`：匹配所有请求路径
- `proxy_pass http://127.0.0.1:8080`：将请求转发到本机 8080 端口的 Tomcat，这是反向代理的核心指令
- `proxy_set_header Host $host`：把用户访问的域名或 IP 传给后端 Tomcat
- `proxy_set_header X-Real-IP $remote_addr`：把用户真实 IP 传给 Tomcat
- `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for`：传递用户来源 IP 的完整链路

## 配置生效步骤

- 执行 `nginx -t` 检查配置语法是否正确，看到 `syntax is ok` 和 `test is successful` 才说明配置没问题
- 执行 `nginx -s reload` 重新加载配置，不需要重启 Nginx

## 验证反向代理

- 在宿主机浏览器访问 http://192.168.149.128
- 能看到 Tomcat 默认页，说明反代配置生效
- 地址栏是 80 端口，不需要加 :8080

## 本环境中实际验证过的细节

- 直接访问 http://192.168.149.128:8080 可以打开 Tomcat 页面
- 通过 http://192.168.149.128 访问，同样显示 Tomcat 页面
- 说明 Nginx 确实把请求转发给了 Tomcat，并且响应正常返回
