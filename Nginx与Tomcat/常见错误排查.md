# 常见错误排查

## 适用场景

Nginx 反向代理 Tomcat 环境搭好之后，通过浏览器访问出现异常时，按错误码定位问题。

## 错误码速查

- 502 Bad Gateway：Nginx 能收到请求，但后端 Tomcat 没起来或连不上
- 403 Forbidden：权限不足，通常和目录或文件权限有关
- 404 Not Found：路径不对，或静态文件不存在
- connection refused：端口没有服务在监听
- timeout：网络不通或防火墙拦截

## 502 Bad Gateway

现象：浏览器访问 http://192.168.149.128 返回 502。

原因：Nginx 把请求转发给 127.0.0.1:8080，但 Tomcat 没有启动，或 8080 端口没有进程监听。

排查步骤：

1. 确认 Tomcat 服务状态

   systemctl status tomcat

   如果不是 active（running），说明 Tomcat 没启动，先启动：

   systemctl start tomcat

2. 确认 8080 端口是否监听

   ss -lntp | grep 8080

   没有输出说明 Tomcat 没监听，继续查日志：

   journalctl -u tomcat -n 50

3. 确认 Nginx 反代配置是否指向正确端口

   nginx -t
   grep -n "proxy_pass" /etc/nginx/nginx.conf

   确认 proxy_pass 指向的是 127.0.0.1:8080，而不是其他端口。

实践场景：环境搭建完成后，曾经因为 Tomcat 未启动，直接访问 80 端口出现 502，启动 Tomcat 后恢复正常。

## 403 Forbidden

现象：访问页面时返回 403，页面被拒绝。

常见原因：

- Nginx 运行用户没有目标目录的读权限
- 目录下没有 index 文件，且开启了 autoindex off

排查步骤：

1. 检查 Nginx 错误日志

   tail -n 50 /var/log/nginx/error.log

2. 查看目录权限

   ls -ld /usr/share/nginx/html

   确认 Nginx 用户（通常是 nginx）对该目录有读和执行权限。

3. 检查 index 配置

   grep -n "index" /etc/nginx/nginx.conf

   如果没有配置 index，且目录下没有 index.html，会直接拒绝访问。

实践场景：该环境以 Tomcat 页面为主，403 未作为独立场景实际演练过，但排查思路已通过其他权限问题验证。

## 404 Not Found

现象：访问某个路径返回 404，页面找不到。

常见原因：

- Nginx 的 root 路径配置错误
- 静态文件放在错误目录
- location 匹配到了不存在的路径

排查步骤：

1. 看 Nginx 错误日志

   tail -n 50 /var/log/nginx/error.log

   会明确提示具体是哪个文件找不到。

2. 检查 root 和 location

   grep -n "root\|location" /etc/nginx/nginx.conf

   确认实际查找的目录和文件放置的目录是否一致。

3. 手动确认文件是否存在

   ls -l /usr/share/nginx/html/文件名

实践场景：之前整理静态资源访问时，出现过 404。最终是文件没放到 root 指定的目录下，调整路径后恢复正常。

## connection refused

现象：宿主机访问 http://192.168.149.128:8080 提示连接被拒绝。

原因：Tomcat 没有启动，或 8080 端口没有被监听。

排查命令：

   ss -lntp | grep 8080
   systemctl status tomcat

和 502 的区别：

- connection refused：客户端直接访问 8080，端口没人监听
- 502：客户端访问 Nginx 80，Nginx 转发到 8080 时后端不通

## timeout

现象：访问 IP 一直转圈，最后提示超时。

原因：

- 防火墙拦截了对应端口
- 虚拟机和宿主机网络不通

排查步骤：

1. 确认防火墙状态和规则

   systemctl status firewalld
   firewall-cmd --list-all

   如果没有放行 8080，先放行：

   firewall-cmd --add-port=8080/tcp --permanent
   firewall-cmd --reload

2. 确认网络连通

   ping 192.168.149.128

   能通说明网络正常，重点检查防火墙。

实践场景：环境搭建时，Tomcat 启动正常、8080 端口已监听，但宿主机访问超时。检查后发现防火墙未放行 8080，放行后恢复。

## 排查顺序建议

外部访问异常时，按以下顺序判断：

1. 端口是否监听：ss -lntp | grep 8080
2. 服务是否运行：systemctl status tomcat
3. 防火墙是否放行：firewall-cmd --list-all
4. Nginx 日志：tail -n 50 /var/log/nginx/error.log
