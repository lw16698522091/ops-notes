# 故障现象速查表

## 用途

遇到异常时，根据现象先判断属于哪一类问题，再选择对应的排查命令。这张表只做方向定位，不展开具体操作。

## 一、端口与连接类

- connection refused（连接被拒绝）
  原因：目标端口没有服务在监听
  排查方向：ss -lntp、systemctl status 服务名

- timeout（连接超时）
  原因：请求发出去没有响应，通常是防火墙拦截或网络不通
  排查方向：firewall-cmd --list-all、ping

- 端口被占用
  原因：其他进程占用了目标端口
  排查方向：lsof -i:端口号、ss -lntp

## 二、HTTP 状态码类

- 502 Bad Gateway
  原因：Nginx 能收到请求，但后端 Tomcat 没启动或连不上
  排查方向：systemctl status tomcat、ss -lntp | grep 8080

- 504 Gateway Timeout
  原因：后端服务有进程，但长时间无响应，超出 Nginx 等待时间
  排查方向：查看后端日志、检查后端服务负载

- 403 Forbidden
  原因：权限不足，或目录禁止索引
  排查方向：ls -ld 目录、Nginx 错误日志

- 404 Not Found
  原因：路径不存在，或文件没有放到 root 指定目录
  排查方向：Nginx 错误日志、ls -l 实际路径

## 三、系统资源类

- 磁盘满
  现象：服务写入文件报错，或命令执行缓慢
  排查命令：df -h、du -sh *
  补充：磁盘满后服务可能不会直接挂掉，但日志和临时文件无法写入，形成隐患

- 内存不足
  现象：系统卡顿，服务被 OOM Killer 杀掉
  排查命令：free -h、dmesg | grep -i oom

- CPU 使用率过高
  现象：服务响应慢，top 显示某进程 CPU 接近 100%
  排查命令：top，按大写 P 排序

- 系统负载过高
  现象：整体响应慢，即使 CPU 不高
  排查命令：uptime、top，结合 CPU 核数判断

## 四、定时任务类

- crontab 不执行
  可能原因：crond 服务未启动、语法写错、脚本没有执行权限、脚本内环境变量缺失
  排查方向：systemctl status crond、crontab -l、查看 /var/log/cron

## 五、静态资源类

- 静态文件 404
  原因：文件没有放在 Nginx root 指定的目录下，或路径写错
  排查方向：检查 root 配置、ls 实际目录

- 静态文件 403
  原因：目录权限不足，或目录下没有 index 文件且禁止列出目录
  排查方向：ls -ld 目录、检查 index 配置

## 六、排查顺序建议

遇到访问异常，先按这个顺序走，避免盲目查日志：

1. 服务状态：systemctl status 服务名
2. 端口监听：ss -lntp | grep 端口号
3. 防火墙规则：firewall-cmd --list-all
4. 对应日志：journalctl -u 服务名、/var/log/nginx/error.log
