系统资源排查

一、适用场景

- 系统响应明显变慢
- 某个服务占用资源过高
- 排查时先摸清 CPU、内存、负载、磁盘的整体情况

二、常用命令组合

- uptime
  查看系统负载，一行输出包含 1分钟、5分钟、15分钟平均负载
  重点：负载高不代表 CPU 满，要看 CPU 核数
  单核系统负载超过 1 算偏高，4核系统负载 3 以内仍然正常

- free -h
  查看内存总量、已用、可用、缓存
  -h 表示以人类易读的 G/M 显示
  重点：free 显示的 available 才是真正可用的内存，不用纠结 buff/cache 数字

- top
  实时查看进程 CPU 和内存占用
  按大写 P：按 CPU 使用率排序
  按大写 M：按内存使用率排序
  按 q：退出
  重点：看 %CPU 和 %MEM 两列，找出异常进程

- df -h
  查看磁盘分区使用率

三、排查思路

第一步 看整体负载

uptime
确认当前负载高低，观察 1分钟和 15分钟负载的差距
如果 1分钟负载远高于 15分钟，说明负载刚刚上升，是最近发生的问题

第二步 看 CPU 和内存

top
按大写 P 看 CPU 占用最高的进程
按大写 M 看内存占用最高的进程
确认是否有进程 CPU 接近 100% 或内存占用异常增长

第三步 看内存细节

free -h
确认 available 是否充足
如果 available 持续走低且不断有服务被终止，说明内存不足

第四步 看磁盘

df -h
确认磁盘使用率
磁盘满会导致写入失败，但表现可能是服务异常而不是直接的资源告警

四、实际演练场景

场景一：内存故障模拟
演练方式：通过模拟方式制造内存压力，观察系统反应
观察结果：free -h 显示可用内存持续下降，最终触发 OOM Killer 杀掉占用内存最高的进程
验证命令：dmesg | grep -i oom，能看到 OOM Killer 的触发记录

场景二：资源占用定位
演练方式：在系统整体卡顿的情况下，用 top 结合 P/M 排序定位占用最高的进程
观察结果：确认异常进程后，结合服务管理命令重启或停止该服务

五、注意点

- top 看 CPU 和内存，free 看内存，df 看磁盘，uptime 看负载，四个命令搭配使用
- 高负载排查时，自问三个问题：
  1. CPU 被打满了吗
  2. 内存够用吗
  3. 磁盘满了吗
- 优先找异常进程，而不是盲目重启服务
- 内存不足时系统可能杀掉进程，现象类似服务自己崩溃，要结合 dmesg 确认是否 OOM
