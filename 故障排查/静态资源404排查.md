静态资源404排查

一、适用场景

- 访问静态页面或静态文件时返回 404
- 文件确实存在，但浏览器就是找不到
- 配置了 location 但实际请求没有匹配到预期路径

二、Nginx 静态资源访问的基本逻辑

用户请求某个路径时，Nginx 根据配置把路径映射到服务器上的实际目录。

涉及两个指令：

- root：把请求路径拼接在 root 指定的路径后面
  示例：root /usr/share/nginx/html;
  请求 /index.html，实际查找 /usr/share/nginx/html/index.html

- alias：把请求路径直接替换为 alias 指定的路径
  示例：alias /data/images/;
  请求 /images/1.jpg，实际查找 /data/images/1.jpg

404 的本质：Nginx 按配置拼接出实际路径后，在磁盘上找不到这个文件。

三、排查步骤

第一步 确认报错细节

tail -n 50 /var/log/nginx/error.log

错误日志中会明确提示 open() 了哪个路径，以及返回 404
这一步能直接看出 Nginx 实际查找的文件路径

第二步 对比实际文件位置

ls -l /实际路径

拿日志中提示的路径和文件真实位置对比
如果路径不一致，说明 root 或 location 配置有误

第三步 检查 root 和 location 配置

grep -n "root\|location" /etc/nginx/nginx.conf

确认配置里写的路径和文件实际存放位置是否一致
注意 root 的路径是否写对，地址最后有没有多写或少写目录层级

第四步 检查文件权限

ls -ld 目录路径

Nginx 用户需要对该路径有读权限
如果文件存在但权限不足，通常返回 403，不是 404，但也要顺手确认

四、实际演练场景

场景：配置静态资源访问后，访问 http://192.168.149.128/静态文件名 返回 404。

排查过程：
1. 查看 Nginx 错误日志，看到 open() 的实际路径
2. 手动 ls 该路径，发现文件不在那里
3. 对比 root 配置和文件真实位置，发现文件放错目录
4. 将文件移动到 root 指定位置，重新访问恢复正常

五、404 和 403 的区别

- 404：Nginx 按路径找文件，文件不存在
- 403：文件存在或目录存在，但没有权限访问

排障时先看错误日志，日志会直接告诉你是 open() 失败还是 permission denied。
