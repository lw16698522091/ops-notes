## 进程健康检查脚本

题目： 检查 nginx 是否在运行，如果没运行则自动拉起，最多重试 5 次，5 次都失败则报错退出。

脚本内容：

```bash
#!/bin/bash
# 获取服务运行状态
i="$(sudo systemctl is-active nginx)"
# 循环计数器
o="0"

# 如服务已启动则输出成功信息并exit退出脚本，否则尝试启动并延迟2秒后检查是否成功启动，计数器自增1，等于5时结束
while [ "$o" -lt 5 ]; do
    if [ "$i" != "active" ]; then
        sudo systemctl start nginx
        sleep 2
        i="$(sudo systemctl is-active nginx)"
        o="$((o+1))"
    else
        echo "nginx 已成功启动, PID: $(ps aux | grep nginx | grep -v grep | awk '{print $2}' | head -1)"
        exit
    fi
done

# 5次未成功启动后，输出失败提示并退出脚本
echo "nginx 启动失败，请检查配置和日志"
exit 1
```

效果说明： 

| 场景 | 输出 |
|------|------|
| nginx 正常运行 | `nginx 已成功启动, PID: 1234` |
| nginx 停止后执行 | 自动拉起，输出 `PID` |
| 启动命令故意写错 | 重试 5 次，输出 `nginx 启动失败，请检查配置和日志` |

关键知识点：

- `systemctl is-active nginx` 判断服务状态，输出 `active/inactive`
- `sleep 2` 给服务启动预留时间
- `$((o+1))` 计数器自增，控制重试次数
- `exit` 提前退出脚本，避免死循环
- 用 `ps aux | grep | grep -v grep | awk '{print $2}'` 取 PID

踩坑记录：
- `grep -c "running"` 在 `systemctl status` 里计数不稳定，改用 `is-active` 更可靠
- `sleep 2` 不能写在 `$(systemctl is-active sleep 2 nginx)` 里面
- `[$o > 5]` 不是数值比较，要用 `-gt`
- `while` 循环里如果成功分支不 `exit`，会死循环

## 磁盘监控脚本

题目： 监控根分区使用率，超过设定阈值（默认 80%）时记录告警信息，便于配合 crontab 定时巡检。

脚本内容：

```bash
#!/bin/bash

# 阈值，超过则告警
THRESHOLD=80
# 监控的分区挂载点
MOUNT="/"
# 告警日志
LOG="/var/log/disk_monitor.log"

# df -P 保证单行输出，awk 取使用率数字（第5列去掉 %）
usage=$(df -P "$MOUNT" | awk 'NR==2 {gsub("%","",$5); print $5}')

if [ "$usage" -gt "$THRESHOLD" ]; then
    msg="$(date '+%F %T') [WARN] 根分区使用率 ${usage}%，超过阈值 ${THRESHOLD}%"
    echo "$msg"
    echo "$msg" >> "$LOG"
else
    echo "$(date '+%F %T') [OK] 根分区使用率 ${usage}%，正常"
fi
```

效果说明：

| 场景 | 输出 |
|------|------|
| 使用率 45%（低于阈值） | `[OK] 根分区使用率 45%，正常` |
| 使用率 88%（高于阈值） | `[WARN] 根分区使用率 88%，超过阈值 80%`，并写入日志 |
| 阈值可调 | 修改 `THRESHOLD` 即可适配不同环境 |

关键知识点：

- `df -P`：POSIX 格式输出，避免挂载点过长时换行导致 awk 取列错位
- `gsub("%","",$5)`：去掉百分号，把字符串转成纯数字用于数值比较
- `-gt`：数值大于比较（字符串比较要用 `>`）
- `>>`：追加写入日志，不覆盖历史记录

配合 crontab 定时执行：

```bash
# 每 5 分钟巡检一次
*/5 * * * * /path/to/disk_monitor.sh
```

部署后可用 `tail -f /var/log/disk_monitor.log` 观察告警输出。

踩坑记录：

- `df -h` 的 `Use%` 在第 5 列，但加了 `-P` 后列顺序稳定，脚本里务必用 `-P` 防止换行。
- 使用率比较必须用数值 `-gt`，写成字符串比较会出错。
- 脚本需要执行权限：`chmod +x disk_monitor.sh`，否则 crontab 调用失败（参见 [crontab 排障](../定时任务/crontab排障.md)）。

## 系统巡检脚本

题目： 监控 CPU、内存、磁盘使用率，超过阈值输出告警，全部正常输出系统正常。

脚本内容：
```bash
#!/bin/bash
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

yz="80" #阈值
disk_path="/"   #磁盘分区
core="$(nproc)"
cpu="$(top -bn3 -d 0.2 | grep '%Cpu' | awk '{printf "%.0f\n",100 - $8}' | sort -n | head -1)"
mem="$(free -h | awk 'NR==2 {printf "%.0f",$3/$2*100}')"
disk="$(df -Th | awk -v v="$disk_path"  '$7==v {gsub("%","",$6);printf "%.0f",$6}')"
load="$(top -bn1 | awk -v v="$core" 'NR==1 {gsub(",","",$11);printf "%.1f",$11/v*100}')"

#数组版
declare -A usage
declare -A label
usage[cpu]="$(top -bn3 -d 0.2 | grep '%Cpu' | awk '{printf "%.1f\n",100 - $8}' | sort -n | head -1)"
usage[mem]="$(free -h | awk 'NR==2 {printf "%.1f",$3/$2*100}')"
usage[disk]="$(df -Th | awk -v v="$disk_path"  '$7==v {gsub("%","",$6);printf "%.1f",$6}')"
usage[load]="$(top -bn1 | awk -v v="$core" 'NR==1 {gsub(",","",$11);printf "%.1f",$11/v*100}')"

label[cpu]="CPU使用率"
label[mem]="内存使用率"
label[disk]="磁盘使用率"
label[load]="系统平均负载"
tik="0"
for key in "${!usage[@]}"; do
        if awk -v v="${usage[$key]}" -v t="$yz" 'BEGIN{exit !(v>=t)}'; then
                echo "警告！！${label[$key]}(${usage[$key]})超阈值($yz)！！"
                tik=$((tik+1))
        fi
done
[ "$tik" -eq "0" ] && echo "系统正常"
for key1 in "${!usage[@]}"; do
        echo "${label[$key1]}:${usage[$key1]}%"
done
#数组版结尾分界
echo "------上面为数组版结果------"
if [ "$cpu" -lt "$yz" ] && [ "$mem" -lt "$yz" ] && [ "$disk" -lt "$yz" ] && awk -v v="$load" -v t="$yz" 'BEGIN{exit !(v<t)}';then
echo -e "系统正常：\n CPU使用率:$cpu% \n 内存使用率:$mem% \n $disk_path分区使用率:$disk% \n 系统平均负载:$load%" 
fi

[ "$cpu" -ge "$yz" ] && echo "警告！！CPU使用率($cpu%)超过$yz%！！" 
[ "$mem" -ge "$yz" ] && echo "警告！！内存使用率($mem%)超过$yz%！！"
[ "$disk" -ge "$yz" ] && echo "警告！！$disk_path分区使用率($disk%)超过$yz%！！"
awk -v v="$load" -v t="$yz" 'BEGIN{exit !(v>=t)}' && echo "警告！！系统平均负载($load%)超过$yz%！！"

```
效果说明：
| 场景 | 输出 |
|------|------|
| 所有指标正常 | `CPU使用率正常: 12.5% (阈值 80%)\n内存使用率正常: 50.0% (阈值 80%)\n磁盘使用率正常: 30% (阈值 80%)\n系统正常` |
| CPU 超过 80% | `CPU使用率异常: 85.2% (阈值 80%)`，最后不输出“系统正常” |
| 内存、磁盘同时超标 | 对应输出两行“异常”信息，计数器累计 |

关键知识点：
- `top -bn3 -d 0.2` 多次采样取最小值，避免偶发 100%
- 关联数组 `declare -A` 配合 `for key in "${!usage[@]}"` 遍历
- `awk printf "%.1f"` 格式化浮点数
- `bc` 命令做浮点数比较，输出 1 表示条件成立，0 表示不成立
- 英文键加中文标签映射，避免中文键编码问题

踩坑记录：
- `top -bn1` 第一帧的 CPU 使用率是系统开机以来的平均值，刚开机时容易显示 100%
- 阈值判断写成 `if [ "$cpu" -ge "$yz" ]` 对浮点数无效，必须用 `bc`
- 关联数组中文键虽然语法支持，但可能出现编码问题，不用

## 批量主机连通性检测脚本（并行版）

题目： 读取 hosts.txt 中的 IP 列表，并行检测每个主机是否在线，最终分别输出在线和离线的主机列表。

脚本内容：

```bash
#!/bin/bash
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

hosts="/home/admin/scripts/hosts.txt"
zx=()
lx=()
tmpdir=$(mktemp -d)

[ ! -f "$hosts" ] && echo "目标文件不存在，请确认文件地址或文件名正确" && exit 1

while IFS= read -r  i || [ -n "$i" ]; do
         (
         ping -W 0.2 -c 1 "$i" >/dev/null 2>&1
         if [ "$?" -eq "0" ]; then
                 echo "$i" >> "$tmpdir/online"
         else
                 echo "$i" >> "$tmpdir/offline"
         fi
         ) &
done < <( grep -vE '^#|^$' "$hosts")

wait

mapfile -t zx < "$tmpdir/online"
mapfile -t lx < "$tmpdir/offline"
rm -rf "$tmpdir"

if [ "${#zx[@]}" -gt "0" ] && echo "---在线IP---" ;then
        for key in "${!zx[@]}"; do
                echo "${zx[$key]}"
        done
fi

if [ "${#lx[@]}" -gt "0" ] && echo "---离线IP---" ;then
        for key in "${!lx[@]}"; do
                echo "${lx[$key]}"
        done
fi

echo "在线数量：${#zx[@]}，离线数量：${#lx[@]}"
```

效果说明：
| 场景 | 输出 |
| hosts.txt 中有可达主机和不可达主机 | 在线主机：192.168.149.128、离线主机：127.0.0.1 |
| 全部不可达 | 在线主机：无、离线主机：192.168.149.128 127.0.0.1 |
| hosts.txt 不存在 | IP列表文件不存在，exit 1 |

关键知识点：
- ( 命令 ) & 放入后台子 shell，循环结束后 wait 等待全部完成
- mktemp -d 创建临时目录，避免多任务同时写同一文件冲突
- mapfile -t 数组名 < 文件 按行读入数组
- grep -vE '^#|^$' 过滤注释行和空行
- 进程替换 < <(命令) 把 grep 结果作为文件输入给 while

踩坑记录：
- 子 shell 内对变量或数组的修改，主 shell 看不到，必须通过文件回传
- [ -f "$wj" ] 中变量写错导致判断失效，用 bash -x 定位
- 忘记 wait 会导致主脚本提前结束，临时目录被删除，回读不到结果

## 备份脚本

题目：​ 备份 /opt/myapp 到 /backup，压缩包命名 myapp_时间戳.tar.gz，只保留最近 7 份。

脚本内容：

```bash
#!/bin/bash
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

path_back="/opt/myapp"

[ ! -d "$path_back" ] && echo "目录不存在，请检查路径是否正确" && exit 1

if mkdir -p /backup ;then
        echo "备份目录已就绪"
else
        echo "备份目录创建失败"
        exit 1
fi

tar -czf /backup/myapp_$(date +%Y%m%d_%H%M%S).tar.gz -C "$path_back" .
if [ "$?" -eq "0" ] ;then
        echo "备份成功"
else
        echo "备份失败"
        exit 1
fi
ls -t /backup/myapp_*.tar.gz | tail -n +8 | xargs rm -f
if [ "$?" -eq "0" ];then
        echo "已保留最近7个，多余备份文件已清理"
        exit 0
else
        echo "清理失败"
        exit 1
fi
```

效果说明：
| 场景 | 输出 |
| 正常执行 | 备份目录已就绪、备份成功、已清理多余备份文件，保留最近7个 | 
| /opt/myapp 不存在 | 目录不存在，请检查路径是否正确，exit 1 |
| 无法创建 /backup | 备份目录创建失败，exit 1，不执行打包 |

关键知识点：
- tar -czf 目标路径 包名 -C 源目录 . 中，-C 进入目录后必须加 . 作为打包对象，. 表示当前目录所有内容，不加 . 会生成空归档
- date +%Y%m%d_%H%M%S 生成时间戳
- ls -t | tail -n +8 | xargs rm -f 按时间排序后从第8个开始删除
- 清理命令限定 /backup/myapp_*.tar.gz，避免误删其他文件

踩坑记录：
- tar 遗漏 . 导致打包出空归档，tar -tzf 验证时只显示 ./
- tar -tzf 接多个文件通配符展开时，会把后面的文件当作归档内成员名查找，报错归档中找不到
- 普通用户无法创建 /backup，测试时用 sudo 运行，cron 里需要 root crontab
- ls -t "/backup/myapp_*.tar.gz" 双引号包裹通配符导致 * 不展开，识别不到文件

## 日志清理脚本

题目： 清理 /var/log/myapp 下修改时间超过 7 天的 .log 文件，支持预览模式和强制删除模式。

脚本内容：

```bash
#!/bin/bash
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
# 日志清理脚本

dry_run="0"
force="0"
LOG_DIR="/var/log/myapp"
DAYS=7

case "$1" in
        --dry_run) dry_run=$((dry_run+1));;
        --force) force=$((force+1));;
esac

if [ ! -d "$LOG_DIR" ]; then
    echo "目录不存在"
    exit 1
fi

files="$(find "$LOG_DIR" -type f -name "*.log" -mtime +7 2>/dev/null)"
[ -z "$files" ] && echo "暂无需要清理的日志" || if [ "$dry_run" -ne "0" ];then
        echo -e "以下为将要删除的文件：\n $files"
elif [ "$force" -ne "0" ];then
        find "$LOG_DIR" -type f -name "*.log" -mtime +7 -exec rm -f {} +
        echo -e "已删除以下文件：\n $files"
else
        echo -e "使用说明：\n sudo ./clean_logs.sh --dry_run 查看将删除的日志\n sudo ./clean_logs.sh --force 自动删除日志"
fi
```
效果说明：

| 场景 | 输出 |
| 不带参数执行 | 使用说明，提示 --dry_run 和 --force 两种用法 |
| --dry_run 且有待清理文件 | 显示“以下为将要删除的文件：”加文件列表 |
| --force 且有待清理文件 | 实际删除，显示“已删除以下文件：”加文件列表 |
| 有待清理文件时 | 输出“暂无需要清理的日志” |
| LOG_DIR 不存在 | 输出“目录不存在”，exit 1 |

关键知识点：
- find 配合 -mtime +7 按修改时间筛选，-mtime +N 表示超过 N 天，-N 表示 N 天内，N 表示恰好 N 天
- find -exec rm -f {} + 批量删除，加号结尾比分号效率更高
- [ -z "$files" ] && echo ... || if ...; then ... fi 三段式判断：空结果提示、有结果按模式处理
- 2>/dev/null 丢弃权限不足的报错，避免无关信息刷屏
- 双引号包裹 $files 防止文件名含空格时被拆分

踩坑记录：
- 判断变量时用 [ -z "$files" ] 而不是直接 [$files ]，因为 $files 为空时 [$files ] 会报参数过多或缺失错误
- 不加 --force 或 --dry_run 时脚本输出使用说明，而不是直接删除，避免误删
- find + mtime 基于修改时间，如果日志被 touch 过会重置时间，可能延迟清理

## 批量添加用户脚本

题目：批量从 users.txt 读取用户名创建用户，密码统一设置为 123456，并将结果分为创建成功、已存在、失败三类输出。

脚本内容：
```bash
#!/bin/bash
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
# 批量创建用户脚本
# 用法：sudo bash create_users.sh

USERS_FILE="users.txt"
[ ! -f "$USERS_FILE" ] && { echo "用户列表文件不存在"; exit 1; }

cg=()
ycz=()
sb=()

while IFS= read -r user || [ -n "$user" ]; do
    useradd "$user" >/dev/null 2>&1
    case $? in
        0) cg+=("$user") ;;
        9) ycz+=("$user") ;;
        *) sb+=("$user") ;;
    esac
done < <(grep -vE '^$|^#' "$USERS_FILE")
if [ "${#cg[@]}" -gt "0" ];then
        for i in "${cg[@]}";do
                echo "123456" | passwd --stdin "$i" >/dev/null 2>&1
        done
fi
[ "${#cg[@]}" -gt "0" ] && echo "=== 创建成功 (${#cg[@]}) ==="
printf '%s\n' "${cg[@]}"
[ "${#ycz[@]}" -gt "0" ] && echo "=== 已存在 (${#ycz[@]}) ==="
printf '%s\n' "${ycz[@]}"
[ "${#sb[@]}" -gt "0" ] && echo "=== 失败 (${#sb[@]}) ==="
printf '%s\n' "${sb[@]}"
```
效果说明：

| 场景 | 输出
| users.txt 中存在可创建、已存在、失败三类用户 | 依次输出 === 创建成功 (N) ===、用户名列表、=== 已存在 (N) ===、用户名列表、=== 失败 (N) ===、用户名列表 |
| users.txt 不存在 | 输出 用户列表文件不存在，exit 1 |
| users.txt 全为注释和空行 | 三个分组都不输出，脚本正常结束 |
| 所有用户创建成功 | 只输出 === 创建成功 (N) === 加用户名列表 |
| 用户已存在 | useradd 返回 9，归入已存在分组，不修改该用户密码 |

关键知识点：
- cg、ycz、sb 三个数组分别记录创建成功、已存在、创建失败的用户
- useradd 的退出码 9 表示用户名已存在，不能简单把所有非 0 都当失败
- 通过 case $? in 0) ... 9) ... *) ... esac 对退出码分类
- while IFS= read -r user || [ -n "$user" ] 可以正确处理文件最后一行没有换行符的情况
- grep -vE '^$|^#' "$USERS_FILE" 过滤空行和注释行，不需要在循环里再单独判断
- printf '%s\n' "${cg[@]}" 数组逐行输出，比 echo ${cg[@]} 更可控
- passwd --stdin 是 RHEL 系写法，Rocky 支持；Debian/Ubuntu 要用 chpasswd

踩坑记录：
- USERS_FILE="users.txt" 是相对路径，从其他目录执行脚本会找不到文件。建议改成绝对路径 /home/admin/scripts/users.txt，或在脚本开头加 cd "$(dirname "$0")"
- passwd --stdin 不是跨发行版通用写法，面试被问到通用方案时，可以说 echo "用户名:密码" | chpasswd
- 脚本只检查了 useradd 是否成功，没有检查 passwd 是否设置成功。如果面试问怎么更严谨，可以在 passwd 后判断退出码，失败时把用户从成功组移到失败组
- 如果用户列表文件带 Windows 换行符，useradd 会把 \r 当作用户名的一部分，需要先 sed 's/\r$//' 处理
- 如果业务需要家目录，useradd 要加 -m 参数，确认系统默认 CREATE_HOME 是否为 yes
