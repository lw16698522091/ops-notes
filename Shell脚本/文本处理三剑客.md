# 文本处理三剑客

> 本模块记录 grep、sed、awk 三个文本处理工具的核心用法，覆盖按行筛选、按行修改、按列处理三类场景。
> 目标：能使用管道组合三剑客完成日志过滤、配置修改、信息提取等日常运维操作。

---

## 一、三剑客定位速查

| 工具 | 核心能力 | 典型场景 |
|------|---------|---------|
| grep | 按行筛选 | 过滤日志关键字、统计出现次数 |
| sed | 按行修改 | 替换配置、删除行、截取范围 |
| awk | 按列处理 | 提取列、数值比较、汇总计算 |

共同特点：都从标准输入或文件读取内容，输出到标准输出，所以能用管道 `|` 串联。

---

## 二、grep 文本过滤

### 常用参数速查

| 参数 | 作用 | 示例 |
|------|------|------|
| `-i` | 忽略大小写 | `grep -i "RUNNING"` |
| `-v` | 反向匹配 | `grep -v "grep"` |
| `-n` | 显示行号 | `grep -n "error"` |
| `-c` | 统计匹配行数 | `grep -c " 404"` |
| `-E` | 扩展正则，支持多条件 | `grep -E " 404$| 500$"` |

### 基础示例

```bash
echo -e "nginx running\nmysql stopped\nredis running" | grep "running"
```

输出：

```text
nginx running
redis running
```

```bash
echo -e "nginx running\nmysql stopped" | grep -v "running"
```

输出：

```text
mysql stopped
```

### 日志排查场景

```bash
# 查找 404 请求（状态码在行尾时用 $ 锚定）
grep -E " 404$| 404 " /var/log/nginx/access.log

# 统计 500 错误次数
grep -c " 500" /var/log/nginx/access.log

# 排除健康检查后统计 500
grep -v "healthcheck" /var/log/nginx/access.log | grep -c " 500"
```

### grep 踩坑记录

- 状态码后面是行尾时，`grep " 500 "` 匹配不到，用 `grep " 500$"`。
- `-E` 多条件时竖线 `|` 两边不能有空格，`grep -E " 404 | 500"` 会把空格也当成匹配条件。
- 数字类关键字（状态码、端口）必须用空格或 `$` 锚定，防止误匹配 1500、5000。

## 三、sed 文本修改

### 常用语法速查

| 语法 | 作用 | 示例 |
|------|------|------|
| `sed -n '2p'` | 打印第 2 行 | `df -Th \| sed -n '2p'` |
| `sed -n '2,4p'` | 打印第 2 到 4 行 | `df -Th \| sed -n '2,4p'` |
| `sed -n '/关键字/p'` | 打印匹配关键字的行 | `sed -n '/rl-root/p'` |
| `sed '/关键字/d'` | 删除匹配关键字的行 | `sed '/iso9660/d'` |
| `sed 's/旧/新/g'` | 全局替换 | `echo "24%" \| sed 's/%//g'` |
| `sed -n '/开始/,/结束/p'` | 范围打印 | `sed -n '/<Connector/,/\/>/p'` |
| `sed -i.bak 's/旧/新/' 文件` | 备份并修改文件 | `sed -i.bak 's/8080/9090/' server.xml` |

### 过滤与删除

```bash
# 删除第一行（表头），再删除包含 iso9660 的行
df -Th | sed '1d;/iso9660/d'
```

作用：一行完成跳过表头和过滤无用分区，可替代 `tail -n +2` 加函数内判断。

### 替换

```bash
# 只替换第一个匹配
echo "nginx nginx nginx" | sed 's/nginx/httpd/'

# 全局替换
echo "nginx nginx nginx" | sed 's/nginx/httpd/g'

# 删除所有百分号
df -Th | sed 's/%//g'
```

输出示例（删除百分号后）：

```text
/dev/mapper/rl-root xfs 26G 6.2G 20G 24 /
```

### 修改文件实战流程

```bash
# 1. 修改前查看
sed -n '/port="8080"/p' /opt/tomcat/conf/server.xml

# 2. 备份并修改
sed -i.bak 's/port="8080"/port="9090"/' /opt/tomcat/conf/server.xml

# 3. 修改后验证
sed -n '/port="9090"/p' /opt/tomcat/conf/server.xml

# 4. 如改错，用备份恢复
cp server.xml.bak server.xml
```

### sed 踩坑记录

- 不加 `g` 只替换每一行的第一个匹配。
- 替换内容包含 `/` 时，改用 `#` 或 `@` 做分隔符，例如 `sed 's#/opt/tomcat#/opt/tomcat9#g'`。
- `-i` 不带后缀只修改不备份，正式操作建议使用 `-i.备份后缀`。
- `-n` 和 `p` 必须配对使用，单独 `sed '2p'` 会把所有行输出一遍。

## 四、awk 按列处理

### 常用语法速查

| 语法 | 作用 |
|------|------|
| `awk '{print $n}'` | 打印第 n 列 |
| `awk 'NR>1 {print}'` | 跳过第 1 行 |
| `awk '$7=="/" {print}'` | 筛选第 7 列等于指定值的行 |
| `awk '{gsub("%","",$6)}'` | 删除第 6 列中的 `%` |
| `awk '条件 {动作}'` | 先过滤，再处理 |
| `awk '... END {动作}'` | 所有行处理完后执行动作 |

### 取列与过滤

```bash
# 输出使用率和挂载点
df -Th | awk '{print $6, $7}'

# 跳过表头，输出使用率和挂载点
df -Th | awk 'NR>1 {print $6, $7}'

# 只输出根分区行
df -Th | awk '$7=="/" {print "根分区使用率:", $6}'
```

### 去字符、判断、输出

```bash
df -Th | awk 'NR>1 && $2!="iso9660" {gsub("%","",$6); if ($6+0 > 20) print $7, $6"%"}'
```

说明：

- `NR>1`：跳过表头
- `$2!="iso9660"`：排除光驱文件系统
- `gsub("%","",$6)`：去掉第 6 列中的 `%`
- `$6+0`：字符串转数字再比较
- `print $7, $6"%"`：输出挂载点和使用率

### awk 踩坑记录

- `df -Th` 比 `df -h` 多一列类型，使用率列号从第 5 列变成第 6 列，挂载点从第 6 列变成第 7 列，列号不能照搬。
- `gsub` 修改的是 awk 处理时的字段值，不影响原文件。
- awk 里的比较运算符和 Shell 相同，但变量不需要加 `$` 前缀。

## 五、三剑客组合实战

### 1. 过滤进程并提取 PID 和命令

```bash
ps -ef | grep nginx | grep -v grep | awk '{print $2, $8, $9}'
```

输出示例：

```text
1209 nginx: master
1212 nginx: worker
1213 nginx: worker
```

### 2. 磁盘监控一键命令

```bash
df -Th | sed '1d;/iso9660/d' | awk '{gsub("%","",$6); if ($6+0 > 20) print $7, $6"%"}'
```

作用：删除表头、排除光驱、去 `%`、比较阈值、输出警告。

### 3. 日志中过滤 500 并提取客户端 IP

```bash
grep " 500" /var/log/nginx/access.log | awk '{print $1}'
```

作用：先按行筛出 500 错误，再按列提取 IP，后续可配合 sort、uniq 统计次数。

---

## 六、学习要点

- 三剑客可随意用管道串联：grep 筛行、sed 改行、awk 处理列。
- 能用一条 awk 完成的事，不一定非要写多个管道。
- 修改文件前先备份，修改后必须验证。
- 排查日志时，数字类关键字必须用空格或正则锚定。
- `tail -n +2` 能跳过表头，`sed '1d'` 更简洁；两者场景不同，选自己读得懂的。
