# crontab 排障

## 适用场景

- 定时任务到时间没有执行
- 脚本手动执行正常，但定时任务不执行
- 需要确认是 crond 服务问题、语法问题、权限问题还是环境变量问题

## crontab 基本概念

- crontab -e：编辑当前用户的定时任务
- crontab -l：查看当前用户的定时任务列表
- crontab -r：删除当前用户的所有定时任务
- 任务格式：分 时 日 月 周 命令
  示例：每天凌晨 2 点执行脚本
  0 2 * * * /path/to/script.sh

### 时间字段规则
- 五个字段顺序：分 时 日 月 周
- 字段范围：分 0-59 | 时 0-23 | 日 1-31 | 月 1-12 | 周 0-7，0和7都表示周日

**常用符号：**
- * 表示任意值
- */n 表示每隔 n 单位
- a,b 表示枚举多个值，如 1,15 表示第1和第15
- a-b 表示范围，如 9-17 表示9点到17点

**快速判断法：**把五个字段按“分 时 日 月 周”读出来，例如 30 3 * * * 是每天3点30分，0 2 * * 1 是每周一凌晨2点整，*/5 * * * * 是每5分钟。

**本练习最终配置：**
admin 用户 crontab（crontab -e 编辑）添加：
0 2 * * 1 /home/admin/scripts/system_check.sh
*/5 * * * * /home/admin/scripts/pingip.sh
root 用户 crontab（sudo crontab -e 编辑）添加：
30 3 * * * /home/admin/scripts/backup.sh

### cron 权限处理
- cron 中不能用 sudo。定时任务执行时没有终端，sudo 无法提示输入密码，会直接失败。
- 需要 root 权限的任务直接放在 root 用户的 crontab 中，即以 root 身份执行。

### cron 路径规则
- cron 中必须写绝对路径，以 / 开头。crontab 里的 ~ 和 ./ 都不会按交互 shell 的方式解析，相对路径会导致找不到脚本。

### cron 环境变量
- cron 执行环境不加载交互式 shell 的环境变量，PATH 默认只有 /usr/bin:/bin。脚本内命令建议使用绝对路径，或脚本开头手动设置 export - PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin。
- 脚本内设置 PATH 比 crontab 顶部设置更稳妥，因为不依赖调用者环境。

## 排障步骤

第一步 确认 crond 服务是否运行

  systemctl status crond

如果服务未启动，定时任务不会触发。
启动：systemctl start crond
设置开机自启：systemctl enable crond

第二步 确认定时任务是否存在

  crontab -l

查看当前用户的任务列表。
如果没有任何输出，说明没有配置定时任务。

第三步 确认语法是否正确

  crontab -l

检查每一行格式是否符合「分 时 日 月 周 命令」。
常见错误：字段数量不对、多余空格、时间范围写错。

第四步 确认脚本是否有执行权限

  ls -l /path/to/script.sh

如果没有 x 权限，任务会执行但脚本跑不起来。
添加权限：chmod +x /path/to/script.sh

第五步 查看 cron 日志

  tail -n 50 /var/log/cron

日志中会记录定时任务的触发时间和执行结果，是定位问题的关键依据。

## 常见原因

- crond 服务未启动：所有任务完全不触发
- 语法写错：任务不执行或执行时间不符合预期
- 脚本无执行权限：任务在执行但脚本失败
- 脚本内环境变量缺失：手动执行正常，定时任务执行时 PATH 不同
  cron 的执行环境不加载交互式 shell 的环境变量
  脚本内命令建议使用绝对路径，或脚本开头手动加载环境变量

## 实际演练场景

场景：配置一个定时任务后，等待时间到达发现没有执行。

排查过程：

1. systemctl status crond 确认服务运行正常
2. crontab -l 确认任务存在且格式正确
3. ls -l 检查脚本权限，发现缺少执行权限
4. chmod +x 添加权限后，下一个周期任务正常执行
