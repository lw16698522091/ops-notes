# 端口与进程

## 适用场景

- 服务启动失败，需要确认进程是否存在

- 客户端连接不上，需要确认端口是否在监听

- 端口被占用，需要定位是哪个进程

- 区分「连接被拒绝」和「连接超时」分别代表什么问题

## 1. 查看端口监听状态
| 命令 | 作用 |
|------|------|
| ss -lntp | 列出当前所有被监听的 TCP 端口及对应进程 |
| ss -lunp | 查看 UDP 端口监听（用法类似，字段变为 -u） |

**常用拆解**：
| 命令 | 作用 |
|------|------|
| -l | 只显示正在监听的端口 |
| -n | 不解析域名，速度快 |
| -t | 只看 TCP |
| -p | 显示占用该端口的进程名和 PID |

**实践场景**：环境搭建时，用它确认 Nginx 是否监听 80 端口、Tomcat 是否监听 8080 端口

## 2. 根据端口找进程
| 命令 | 作用 |
|------|------|
| lsof -i:8080 | 精确查看某个端口被哪个进程占用；输出会显示进程 PID、进程名、占用协议 |

**用途**：如果 8080 被其他程序占用了，用这个命令找出来再处理

## 3. 根据进程名找进程
| 命令 | 作用 | 示例 |
|------|------|------|
| ps -ef \| grep 服务名 | 列出包含服务名的所有进程 | 示例：ps -ef \| grep nginx；如果输出里只有 grep 本身那一行，说明服务没有运行 |
| pgrep -l 服务名 | 只显示进程 PID 和名称，比 ps \| grep 更干净 | 示例：pgrep -l nginx；如果没有任何输出，表示没有匹配的进程 |
| ps -ef \| grep 端口名 | 这一条通常配合「按端口找进程」，先 lsof 拿到 PID，再用 ps 看进程详情 |

## 4. 查看进程资源占用
| 命令 | 作用 |
|------|------|
| top | 实时显示进程 CPU 和内存占用 | 

**使用技巧**：
- 按大写 P：按 CPU 使用率排序
- 按大写 M：按内存使用率排序
- 按 q：退出

**口诀回顾**：top 看 CPU，free 看内存，df 看磁盘

## 5. 强制结束进程
| 命令 | 作用 |
|------|------|
| kill PID | 温和结束进程 |
| kill -9 PID | 强制结束进程 |

**注意**：-9 是强杀，可能造成数据丢失或服务状态异常，优先使用普通 kill，实在结束不掉再用 -9

**kill 的完整流程**：
  先 ps 或 pgrep 找到 PID → kill PID → 等几秒 → 再查进程是否还在 → 还在再考虑 kill -9

## 6. 连接异常时的分层判断

这是排查思路的重点，把现象和命令对应起来：
| 现象 | 解释 | 排查 |
|------|------|------|
| 连接被拒绝（connection refused） | 意思是：目标端口没有服务在监听 | 排查命令：ss -lntp 确认端口是否在监听；ps -ef 确认进程是否启动 |
| 连接超时（timeout） | 意思是：请求发出去没有响应，通常是防火墙拦截或网络不通 | 排查命令：先检查防火墙是否放行端口，再确认虚拟机和宿主机网络是否正常 |
| 403 权限拒绝 | 通常是目录或文件的权限不足 | 和使用 ss/ps 无关，属于权限排查范围 |
| 502 Bad Gateway | 反向代理能通，但代理的后端服务没起来或连不上 | 对应检查：后端 Tomcat 进程是否存在、是否在对应端口监听 |
