# 文件与目录操作

> 本模块记录 Linux 文件与目录相关的基础命令，并结合本人在学习过程中遇到的真实排障场景，说明命令的实际用途。
> 目标：不仅会敲命令，更要理解命令在运维排障中的作用。

---

## 一、基础命令速查

| 命令 | 作用 | 常用选项 / 示例 |
|------|------|-----------------|
| `pwd` | 显示当前所在目录的完整路径 | `pwd` |
| `cd` | 切换目录 | `cd /home`、`cd ..`（上级）、`cd ~`（家目录） |
| `ls` | 列出目录内容 | `-l` 详情、`-a` 含隐藏、`-h` 人类可读、`-S` 按大小排序 |
| `mkdir` | 创建目录 | `-p` 递归建多层：`mkdir -p a/b/c` |
| `touch` | 创建空文件 / 更新时间戳 | `touch test.txt` |
| `cp` | 复制 | `-r` 复制目录、`-p` 保留属性 |
| `mv` | 移动 / 重命名 | `mv old.txt new.txt` |
| `rm` | 删除 | `-r` 递归、`-f` 强制；**`rm -rf` 务必确认路径** |
| `ln -s` | 创建软链接（快捷方式） | `ln -s 源文件 链接名` |

## 二、运维实战补充

以下内容均来自本人的实际练习与排障经历，不只是语法，重点在于「什么时候用、为什么用」。

### 1. 磁盘满排障中的命令联动

磁盘满是最常见的运维告警之一，排查思路是「先看整体 → 再逐级定位 → 最后清理」：

```bash
df -h                # 查看各分区使用率，快速判断哪块盘满了
du -sh /var/*        # 统计某目录下各子项大小，逐级往下找
find / -xdev -size +200M   # 查找超过 200M 的大文件
```

**本人实践**：曾通过 `df -h` 发现 `/` 分区使用率达 95%，再用 `du -sh /var/log/*` 定位到某个日志文件过大，最终清理后恢复正常。这套流程已整理至「故障排查/磁盘满排障.md」。

### 2. 删除文件的运维习惯

删错文件是无法恢复的，养成「先确认、再删除」的习惯：

```bash
ls -lh 文件名        # 删除前先确认大小、时间、路径
du -sh 目录          # 确认目录总大小
mv 文件 /tmp/        # 不确定时先移到临时目录，观察服务正常后再删
```

**注意**：删日志文件时，如果服务仍持有该文件的句柄，`rm` 后磁盘空间可能不会立即释放，需要先重启服务或用下面的截断方式。

### 3. 日志文件的安全截断

工作中不能直接 `rm` 正在被写入的日志，推荐使用截断方式清空内容、但保留文件本身：

```bash
> /var/log/messages      # 清空文件内容，inode 不变，服务可继续写入
```

**本人实践**：排查磁盘满时，发现直接 `rm` 大日志后 `df` 显示空间未释放，原因是进程仍持有句柄；改用 `> 文件` 截断后立刻生效。

### 4. 软链接的实际应用

`ln -s` 常用于把编译安装的软件命令软链接到系统 PATH 中，避免每次敲全路径：

```bash
ln -s /usr/local/nginx/sbin/nginx /usr/bin/nginx
# 之后就可以直接用 nginx -t、nginx -s reload
```

**本人实践**：搭建 Nginx 环境时即用此方法，将 nginx 二进制链接到 `/usr/bin`，便于全局调用。

### 5. 路径断点排查（namei）

当遇到「文件明明存在却访问不到」的问题时，可用 `namei` 逐层检查路径的权限与是否存在：

```bash
namei -l /var/www/html/image/test.png
```

会逐层输出每一级目录的权限，快速定位「哪一层缺失或权限不足」。

**本人实践**：在「静态资源 404 专项排查」中使用过，详见「故障排查/静态资源404排查.md」。

### 6. 文件时间戳与按时间查找

`find -mtime` 可以按修改时间筛选文件，常用于清理过期日志：

```bash
find /var/log -mtime +7 -name "*.log"   # 查找 7 天前的日志文件
touch -d "2025-01-01" test.txt          # 手动修改文件时间戳（练习用）
```

## 三、学习要点

- 文件名、目录名尽量使用英文和下划线，避免中文带来的编码与脚本兼容问题。
- `rm -rf` 属于高危操作，执行前务必 `ls` 确认路径。
- 排障类命令（`df`、`du`、`find`、`namei`）的价值在于「定位问题」，要多结合实际场景练习。
- 本模块命令是后续所有排障操作的基础，建议配合「03_故障排查」各案例对照理解。
