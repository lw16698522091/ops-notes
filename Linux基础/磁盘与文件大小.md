# 磁盘与文件大小

## 适用场景

- 磁盘空间告警（使用率超过85%）

- 日志文件过大占用空间

- 需要定位大文件并清理

## 1. 查看磁盘使用率
| 命令 | 作用 |
|------|------|
| df -h | 显示文件系统总大小、已用、可用、使用率、挂载点 |
| -h | 表示以人类可读的单位显示（G/M） |
| df -i | 查看 inode 使用率；当磁盘空间还有剩余，但报“设备上没有空间”时，可能是 inode 用满 |

## 2. 查看文件或目录占用空间
| 命令 | 作用 | 示例和用途 |
|------|------|------|
| du -sh 目录 | 统计指定目录总大小 | 场景示例：du -sh /var/log 查看日志目录总共占用多少空间 |
| du -sh 目录/\* | 列出该目录下每个子目录或文件的大小 | 场景示例：du -sh /var/\*；用途：逐级确认大文件到底在哪个目录 |
| du -sh \* \| sort -rh | 按大小倒序排列 | 用途：快速找出最大的目录或文件 |

## 3. 查找大文件

- find / -xdev -size +200M

  查找超过 200M 的文件

  -xdev 表示不跨文件系统，避免扫描 /proc 等虚拟目录造成干扰

  场景示例：find /var/log -size +100M 找单个超过100M 的日志文件

- ls -lhS /var/log/

  查看目录下文件并按大小倒序排列

  用途：快速看到日志目录里哪些文件最大

## 4. 清理磁盘空间的常见手法

- rm 文件

  删除确认无用的文件

  删日志前先确认大小和路径，必要时先 mv 到临时目录，确认服务正常后再真正删除

- > /var/log/messages

  清空文件内容而不删除文件本身

  适用场景：日志文件被服务占用，直接 rm 会导致文件句柄不释放，空间不会立即回收

  注意：某些服务需要重启后才能重新写入日志

- truncate -s 0 /var/log/nginx/access.log

  和 > 类似，将文件截断为0字节，文件仍然存在

## 5. 定位占用空间的进程文件

- lsof | grep deleted

  查找已被删除但仍被进程占用的文件

  场景：删除了大文件但 df -h 显示空间没释放，大概率是有进程仍持有该文件句柄

  处理方式：重启对应进程或服务，空间才会真正回收

- 备选：lsof +L1

  列出所有存在 deleted 状态的文件

## 6. 日志轮转简述

- logrotate 是系统自带的日志切割工具

- 可以按大小或时间自动切割日志，避免单个日志无限增长

- 以后在真实服务器上需要重点掌握，目前属于了解范围
