# 服务管理

## 1. 服务状态查询

- `systemctl status 服务名`：查看服务运行状态、最近日志、进程 PID，排障第一步通常用它确认服务是否活着

  **实践场景**：搭建 Nginx 反代 Tomcat 时，用 `systemctl status nginx` 确认 Nginx 是否正常运行，用 `systemctl status tomcat` 确认 Tomcat 是否在监听 8080

- `systemctl is-active 服务名`：简洁输出服务是否 `active`；适合脚本里判断服务状态

## 2. 服务启动与停止
|------|------|
| `systemctl start 服务名` | 启动服务 |

| `systemctl stop 服务名` | 停止服务 |

| `systemctl restart 服务名` | 重启服务；改了配置文件后常用 |

| `systemctl reload 服务名` | 重新加载配置；不中断服务 |

  **注意**：Nginx 支持 reload，执行 nginx -s reload 或 systemctl reload nginx；但并非所有服务都支持 reload，不支持时用 restart

## 3. 开机自启管理

- `systemctl enable 服务名`：设置开机自启

  **实践场景**：搭建完成后，给 Nginx 和 Tomcat 都执行了 enable，确保重启虚拟机后服务自动起来

- `systemctl disable 服务名`：取消开机自启

- `systemctl is-enabled 服务名`：查看服务是否已设置开机自启

## 4. 查看监听端口与对应服务

- `ss -lntp`：列出所有监听端口及对应进程；`-l`：监听状态，`-n`：不解析域名，`-t`：TCP，`-p`：显示进程

  **实践场景**：排障时用它确认 8080 端口是否被 Tomcat 监听、80 端口是否被 Nginx 监听；如果端口没有进程监听，对应就是连接被拒绝（refused）

- `ps -ef | grep 服务名`：查看某个服务的进程是否存在；和 `ss -lntp` 配合使用

## 5. 查看服务日志

- `journalctl -u 服务名`：查看某个服务的全部日志

- `journalctl -u 服务名 -f`：实时跟踪该服务日志，排障时常用

- `journalctl -u 服务名 --since today`：查看今天的日志，避免输出过长

  **实践场景**：Tomcat 启动失败时，用 `journalctl -u tomcat` 查看启动报错原因

## 6. 常见服务管理场景

- Nginx 配置改完后：nginx -t 先检查语法，再 systemctl reload nginx；语法不对直接 reload 会导致服务异常，一定要先检查再加载

- 修改了 Tomcat 的 server.xml 端口后：需要 systemctl restart tomcat，reload 不一定生效

- 防火墙和 SELinux 也属于服务，可以用 systemctl status firewalld、systemctl status sshd 查看状态


## 6.4 查看所有服务与开机自启状态

- `systemctl list-unit-files --type=service`：列出所有服务及其开机状态（enabled/disabled/static/alias）
- `systemctl list-units --type=service --state=running`：只列出正在运行的服务
- `systemctl is-active 服务名`：简洁判断当前是否运行
- `systemctl is-enabled 服务名`：简洁判断是否开机自启

STATE 列含义：

| 状态 | 含义 |
|------|------|
| enabled | 开机自启 |
| disabled | 不开机自启，可手动启动 |
| static | 无法直接设置自启，通常由其他服务依赖时自动拉起 |
| alias | 是另一个服务名的别名 |

## 6.5 reload 与 restart 的区别

| 命令 | 行为 | 适用场景 |
|------|------|----------|
| `systemctl reload 服务` | 重新读取配置，**不中断**当前服务 | 改配置后热加载（如 nginx） |
| `systemctl restart 服务` | 完全停止再启动，会断开连接 | 更新程序版本、修复崩溃状态 |

**要点**：改 nginx 配置优先 `reload`，避免中断访问；改 Tomcat 的 server.xml 端口时 `reload` 不一定生效，需用 `restart`。

## 6.6 journalctl 进阶用法

| 命令 | 作用 |
|------|------|
| `journalctl -u 服务名 -n 20 --no-pager` | 查看最近 20 行，不分页 |
| `journalctl -u 服务名 -f` | 实时跟踪，类似 `tail -f` |
| `journalctl -u 服务名 -p err` | 只看 error 级别以上，过滤 info |
| `journalctl -u 服务名 --since "2026-09-14 17:00" --until "18:00"` | 查看指定时间段的日志 |
| `journalctl -u 服务名 --since today` | 查看今天的日志 |
| `journalctl -u 服务名 -b` | 只看本次启动以来的日志 |

**踩坑记录**：`systemctl reload` 只重载配置、不会清空历史日志。检查配置是否真的通过，用 `nginx -T 2>&1 \| grep -i warn`，而不是 `systemctl status`（里面是旧日志，仍会显示过去的 warning）。
