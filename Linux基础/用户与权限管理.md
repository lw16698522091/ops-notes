# 用户与权限管理

> 本模块记录 Linux 多用户系统下的权限模型、权限修改命令、属主属组管理以及 sudo 授权机制。
> 目标：能看懂权限位、能正确赋权、能独立给普通用户配置 sudo 权限，为日常运维和面试打好基础。

---

## 一、权限位速查

`ls -l` 输出的第一列拆解：

```text
-rw-r--r--.
```

| 位置 | 含义 |
|------|------|
| 第 1 位 | 文件类型：`-` 普通文件，`d` 目录，`l` 软链接 |
| 第 2-4 位 | 属主（user）权限 rwx |
| 第 5-7 位 | 属组（group）权限 r-x |
| 第 8-10 位 | 其他用户（other）权限 r-- |
| 第 11 位 | SELinux 标记（`.` 或 `+`），一般忽略 |

**r / w / x 对应的数字：**

| 字母 | 含义 | 数字 |
|------|------|------|
| r | 读 | 4 |
| w | 写 | 2 |
| x | 执行 | 1 |
| - | 无权限 | 0 |

数字求和得到常用权限：

| 数字 | 展开 | 典型用途 |
|------|------|----------|
| 755 | rwxr-xr-x | 可执行程序、目录，属主可写，其他人只读+执行 |
| 644 | rw-r--r-- | 普通文本/配置文件，属主可读写，其他人只读 |
| 600 | rw------- | 私钥等敏感文件，仅属主可读写 |

## 二、chmod 修改权限

**数字方式（整体设置）：**

```bash
chmod 755 test.sh
chmod 644 config.txt
```

**字母方式（精确调整某一类用户）：**

| 符号 | 含义 |
|------|------|
| u | 属主 |
| g | 属组 |
| o | 其他用户 |
| a | 所有人（u+g+o） |
| + / - / = | 添加 / 移除 / 直接赋值 |

```bash
chmod +x test.sh        # 所有人加执行权限
chmod u+x test.sh       # 仅属主加执行
chmod g-w test.sh       # 移除属组写权限
chmod o-r test.sh       # 移除其他用户读权限
chmod a=rw test.sh      # 所有人设为读写
```

---

## 三、chown 修改属主与属组

```bash
chown root test.txt                 # 只改属主
chown root:root test.txt            # 同时改属主和属组
chown :admin test.txt               # 只改属组
```

**注意**：修改属主通常需要 root 权限，要加 `sudo`。改属主和改权限是两件独立的事，互不影响。

## 四、sudo 授权机制

sudo 不是"临时变成 root"，而是**授权普通用户以 root 身份执行单条命令**。命令执行完立刻回到普通用户身份。

查看当前用户的 sudo 授权范围：

```bash
sudo -l
```

输出 `(ALL) ALL` 表示可以以任何用户身份执行任何命令，即拥有完整 sudo 权限。

**给用户配置 sudo 权限（推荐加入 wheel 组）：**

```bash
sudo usermod -aG wheel 用户名
```

因为 `/etc/sudoers` 中默认包含 `%wheel ALL=(ALL) ALL`，加入 wheel 组即可自动获得授权。

**sudoers 语法四段：**

```text
用户名  主机=(可切换身份)  可执行的命令
```

## 五、用户与组管理

| 命令 | 作用 |
|------|------|
| `useradd 用户名` | 创建用户 |
| `passwd 用户名` | 设置/修改密码 |
| `userdel 用户名` | 删除用户，保留家目录 |
| `userdel -r 用户名` | 删除用户及其家目录 |
| `usermod -aG 组名 用户名` | 将用户加入附加组（保留原有组） |

**踩坑记录：**

- `userdel` 报 `user is currently used by process PID`：该用户还有进程在运行。先 `sudo pkill -u 用户名` 或 `sudo kill -9 PID` 杀掉进程，再删除。
- 杀掉用户进程时若当前 shell 正是由该用户启动，`kill -9` 会导致当前终端崩溃、无法输入，重开终端即可。
- `passwd` 设置密码太短或太简单会被拒绝，需满足系统密码策略。

## 六、运维实战补充

- 权限设计遵循最小权限原则：服务账号只给必要权限，配置文件推荐 644、密钥类推荐 600。
- 排查"明明有文件却访问不到"时，用 `namei -l 路径` 逐层检查每一级目录权限。
- 属主变更（`chown`）和权限变更（`chmod`）是两个独立操作，常配合使用。

---

## 七、学习要点

- 权限位是面试必考：rwx 对应数字、755/644 含义必须烂熟。
- 数字方式和字母方式各有适用：整体设置用数字，精确调整某类用户用字母。
- sudo 的本质是"授权单条命令"，不是"持续变 root"；`sudo -i` / `su -` 才是切换 shell。
